# Restic Backup — C:\ and D:\ → External Drive I:

Backs up the entire `C:\` and `D:\` drives to an external hard drive (letter
**`I:`**) using [restic](https://restic.net/), with native Windows VSS
snapshots (`--use-fs-snapshot`) so files in use are still captured
consistently. Since the drive isn't always connected, a background watcher
(`Watch-DriveConnect.ps1`) starts at logon and automatically kicks off a
backup **each time drive I: is plugged in** — no fixed daily schedule needed.

## Files

| File                          | Purpose                                                    |
|--------------------------------|-------------------------------------------------------------|
| `restic-excludes.txt`          | Patterns excluded from every backup (pagefile, temp, etc.) |
| `backup.ps1`                   | Main worker script; backs up to `I:\restic-backup\<hostname>` |
| `Watch-DriveConnect.ps1`       | Background watcher; runs `backup.ps1` when I: is connected |
| `Setup-ResticBackupTask.ps1`   | One-time setup: password file + Scheduled Task registration |
| `restic-password.txt`          | Repository encryption password (generated by setup script, **do not commit/share**) |
| `restic-cache\`                | restic's local metadata cache (safe to delete, will be rebuilt) |
| `logs\backup-YYYYMMDD.log`     | Daily run logs (last 30 kept automatically)                |
| `logs\watcher.log`             | Watcher activity log (drive connect/disconnect events)     |
| `last-backup.txt`              | Marker (date) tracking the last day a backup completed     |
| `last-prune.txt`               | Marker tracking when `forget --prune` last ran             |

## One-time setup

1. **Install restic**:
   ```powershell
   winget install restic.restic
   ```
   Open a *new* PowerShell window afterwards so PATH is refreshed.

2. **Run the setup script** from an elevated PowerShell prompt (right-click
   PowerShell → Run as Administrator), as the account that will run backups:
   ```powershell
   cd C:\Users\ikanis\backup
   .\Setup-ResticBackupTask.ps1
   ```
   This generates `restic-password.txt` (locked down so only your user
   account can read it) and registers the `ResticBackupWatcher-I` Scheduled
   Task, which starts `Watch-DriveConnect.ps1` at logon (runs hidden,
   restarts itself if it stops).

   **⚠️ Back up `restic-password.txt` somewhere safe (e.g. a password
   manager). If it's lost, the backups cannot be decrypted/restored.**

3. **Plug in drive I:** and let the watcher pick it up automatically, or
   **test it manually** right away:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\backup.ps1
   ```
   Watch `logs\backup-<today>.log` for progress. The very first run will
   also `restic init` the repository and then copy a full backup of both
   drives, which can take a long time and a lot of space on I: — consider
   adding more excludes first (media libraries, VM images, etc.) if space is
   a concern.

## How the watcher works

`Watch-DriveConnect.ps1` runs continuously in the background (started at
logon by the scheduled task) and subscribes to a WMI `Win32_VolumeChangeEvent`
(device-arrival) notification. Whenever a volume is assigned drive letter
`I:`, it immediately launches `backup.ps1`. If I: is already connected when
you log on, it triggers a backup right away too. `backup.ps1` itself simply
exits (no error) if I: isn't present, so it's always safe to run manually
regardless of watcher state.

`backup.ps1` only performs one actual backup per calendar day: it records
today's date in `last-backup.txt` after a successful (or warnings-only) run
and skips immediately if that marker already matches today. This means
plugging/unplugging the drive multiple times in a day, or running the
script manually again, won't trigger duplicate backups — delete
`last-backup.txt` if you ever need to force another backup the same day.

## Checking status

```powershell
Get-ScheduledTaskInfo -TaskName ResticBackupWatcher-I
Get-Content .\logs\watcher.log -Tail 50
Get-Content .\logs\backup-$(Get-Date -Format yyyyMMdd).log -Tail 50
```

List snapshots (with I: connected):
```powershell
$env:RESTIC_REPOSITORY = "I:\restic-backup\$env:COMPUTERNAME"
$env:RESTIC_PASSWORD_FILE = "C:\Users\ikanis\backup\restic-password.txt"
restic snapshots
```

## Restoring

Restore the latest snapshot (or a specific one from `restic snapshots`) to
an alternate folder to avoid overwriting current files:
```powershell
$env:RESTIC_REPOSITORY = "I:\restic-backup\$env:COMPUTERNAME"
$env:RESTIC_PASSWORD_FILE = "C:\Users\ikanis\backup\restic-password.txt"
restic restore latest --target C:\restore-test
# or a specific snapshot id / specific path:
restic restore <snapshot-id> --target C:\restore-test --include "C:\Users\ikanis\Documents"
```

### GUI restore (optional)

For browsing snapshots and restoring individual files/folders without the
CLI, use [restic-browser](https://github.com/emuell/restic-browser) — a free,
cross-platform desktop GUI for restic. Point it at the repository path
(`I:\restic-backup\<hostname>`) and `restic-password.txt` to browse and
restore.

## Retention

After each successful backup (throttled to at most once every 7 days), the
script prunes old snapshots, keeping:
- 21 daily snapshots
- 4 weekly snapshots
- 6 monthly snapshots

Adjust `$KeepDaily` / `$KeepWeekly` / `$KeepMonthly` at the top of
`backup.ps1` if you want a different policy.

## Notifications

If a backup or prune run fails, a Windows toast/balloon notification pops up
with the error summary and a pointer to the log file. Successful runs are
silent (check the logs if you want confirmation).

## Uninstalling

```powershell
Unregister-ScheduledTask -TaskName ResticBackupWatcher-I -Confirm:$false
```
The repository on I: and local files in this folder are left untouched;
delete them manually if you want to fully remove the backup.
